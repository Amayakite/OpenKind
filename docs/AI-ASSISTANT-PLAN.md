# AI 助理规划

状态：首版已实现。OpenKind 的常规功能继续可以不联网、无需 AI 使用。

## 目标与体验

让用户用自然语言描述偏好，例如“办公文件用 WordCraft、GridCraft 和 DeckCraft，图片继续用预览”。助理根据当前列表、系统候选应用和用户偏好生成建议，展示“文件类型 / 当前应用 / 建议应用 / 原因”，由用户逐项或多选后确认应用。可询问原因，也可明确保留某些现有设置。

提供商、模型与用途应在界面中明确可见。请求前显示计划发送的摘要，让用户选择涉及哪些类型；至少在首次使用和数据范围发生变化时明确征得同意。默认不发送文件内容、文件名、完整路径、账号信息或完整软件清单，只发送本次任务涉及的扩展名、当前应用名称及经系统判定的候选应用（含为稳定匹配所需的 bundle ID）。这些元数据仍可能反映用户的软件使用习惯；界面允许检查与取消。结果与错误信息默认不持久化；诊断日志须脱敏且可关闭。

## 接入与密钥

1. 设置页支持 OpenAI 与自定义 OpenAI 兼容服务，分别配置 Base URL、模型 ID 和可选 API Key；支持无密钥的本地代理。切换配置时不跨服务复用密钥。
2. 将 API Key 使用 macOS Keychain 保存，按配置隔离；提供替换、删除与连接测试。普通偏好仅存服务名称、端点和模型等非机密配置。错误、日志、崩溃报告和 Git 仓库中不得出现密钥。
3. OpenAI 适配器优先评估 Responses API；自定义兼容服务先面向 `/v1/chat/completions`，并把端点和能力当作可配置项，不能假设所有“兼容”服务支持 Responses、结构化输出、工具调用或相同模型。模型 ID 由用户提供，避免硬编码将来失效。
4. 正常远程端点只允许 HTTPS；若支持本机 HTTP，应仅限 loopback 并在界面明示。不要将凭据发送到其他地址，重定向、代理、请求超时与错误处理需要明确测试。
5. 评估 [MacPaw/OpenAI](https://github.com/MacPaw/OpenAI)：社区维护，支持 Swift 并发、自定义地址及 Responses 接口，也被 [OpenAI 文档列为社区库](https://developers.openai.com/api/docs/libraries)。引入之前检查其许可证、版本、支持的 macOS/Swift、可用接口和第三方兼容性；用 SPM 固定可审计的版本。库是候选，若无法满足兼容性则用 `URLSession` 实现轻量适配器。不要在尚未确定方案时引入依赖。

## 推荐结果与系统边界

应用将候选数据传给模型，模型只返回建议，不直接执行 shell、读取文件或调用系统写入接口。建议结构例如：

```json
{
  "recommendations": [
    {"extension": "docx", "candidate_id": "ai.storyteller.wordcraft", "reason": "适合处理 Word 文档"}
  ],
  "notes": []
}
```

优先使用提供商支持的 JSON Schema 结构化输出，否则按该协议解析 JSON；两种情况都必须本地验证。验证包括扩展名属于本次请求、应用 ID 属于该格式的系统候选集合、每项唯一、数量/文本长度有界、应用仍存在。模型可能拒绝、截断、输出错误或产生不可靠理由；此时显示错误或不确定项，不能自动更改。参考 [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。

应用前重新读取当前关联并检查候选，若用户确认后配置已变化则要求重新预览。按 macOS 内容类型去重并提示可能共同受影响的扩展名。逐项调用系统接口并读回，显示成功、失败、取消及剩余项；失败后不伪称整体成功。变更前记录可恢复的旧值，允许用户尝试逐项恢复；对于系统不支持恢复为“无默认值”、旧应用已卸载或系统拒绝的情况，应明确报告，不能保证完整回滚。

## 首版实现与已知限制

已实现 OpenAI Responses 和自定义 Chat Completions 接口、手动输入或拉取模型、钥匙串密钥、逐次发送预览、建议校验、逐项应用和本会话内尝试恢复。使用 `URLSession` 直接封装窄接口，避免为有限需求引入额外依赖；后续根据提供商兼容性再重新评估社区 SDK。获取模型列表同时用于基本连通性检查；未实现独立的模型生成能力测试，也不保证列出的模型都可用于建议。

支持保存和切换多个配置，并提供 OpenAI 与 DeepSeek 预设；密钥按配置、接口类型和服务地址隔离，旧版密钥按旧地址兼容读取。用户可手动输入新模型 ID。不保证兼容所有供应商的扩展协议。模型结果和恢复记录只保存在当前视图的内存里；离开该页或退出应用后不保证保留。首次实现不保存会话历史、不进行自动重试，也不主动降级模型输出格式。候选最多展示和发送每种类型 30 个；结果应以系统当前状态为准。

## 模块与后续阶段

1. **建议基础（首版已实现）**：抽象已安装应用/类型快照、候选推荐和变更预览；支持不调用 AI 的手动选择、差异展示、逐项应用与恢复尝试。让现有 UI 和日后的助理共用这条路径。
2. **提供商设置（首版已实现）**：引入 `AIProvider` 协议与可注入的 transport，完成 Keychain、端点设置、显式数据预览、连接测试和错误处理。用 mock 服务覆盖授权、超时、兼容性与取消，不要求 CI 持有真实 API Key。
3. **建议生成（首版已实现）**：实现 OpenAI / 兼容端点适配器、受限推荐协议、本地校验、空结果和不可兼容项展示；新增助理会话/建议预览页，完成用户确认后调用阶段 1 的应用流程。
4. **增强**：在真实使用反馈基础上考虑批量筛选、推荐历史、更多提供商能力，以及仅在隐私和性能可控后评估本地模型。切换提供商或模型不影响手动管理。

## 验收

- 连接、断网、无效密钥、取消、限流和第三方不支持特性的情况均有清晰反馈。
- 用户可查看实际发送的数据范围，默认不包含文件内容和路径；凭据不进入日志和持久化会话。
- 伪造应用、重复类型、未知类型、损坏 JSON、模型拒答和过期快照不会触发写入。
- 批量应用逐项反馈，可恢复项可尝试恢复；系统确认或拒绝被真实反映。
- 自动化测试覆盖协议与规则，系统写入通过注入的假服务测试；真实系统接口仅在隔离的人工验收中测试并恢复原设置。
